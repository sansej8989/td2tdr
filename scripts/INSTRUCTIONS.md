# Інструкція: тестові та публічні версії модуля td2tdr

## Що за скрипти

| Скрипт | Що робить | Результат | Чіпає GitHub? |
|---|---|---|---|
| `scripts/build_test.sh` | Збирає тестовий zip (alpha/beta) локально | `dist/td2tdr_v<версія>-<мітка>.zip` + sha256 | Ні |
| `scripts/bump_version.sh` | Піднімає version/versionCode у `module.prop` та `update.json` | 0.0.002 -> 0.0.003 | Ні |
| GitHub Actions `release.yml` | Запускається по тегу `v*` | Публічний zip + Release + `update.json` у репо | Так |

---

## 1. Тестова версія (альфа/бета) — тільки для тебе

Тестовий zip нічого не публікує. Публічна версія в GitHub лишається недоторканою.

### Кроки

1. Внеси правки в код (webroot/, service.sh, customize.sh тощо).
2. Збери тестову збірку:

   ```bash
   bash scripts/build_test.sh alpha    # або beta
   ```

   Результат: `dist/td2tdr_v0.0.002-alpha.zip` + sha256.
   Кожна збірка **перезаписує той самий файл** — старі версії не лишаються.
3. Залий zip на телефон (Tg, кабель, хмара).
4. На телефоні: Magisk або KernelSU → Модулі → **Встановити з файлу** → обери zip.
5. Тестуй: синхронізація, WebUI (http://localhost:8080), вміст `Download/td2tdr_sync`, лог у WebUI.
6. Якщо баги — прав код і повторюй з кроку 2 (нова збірка тим самим скриптом).
7. Коли все ок — переходь до публічної версії (§2).

### Важливо

- Скрипт **не змінює** `module.prop` і `update.json` у репо. У менеджері модуль показує `0.0.002`, а не `0.0.002-alpha`. Це нормально — тестер один, ти.
- Поки не створиш тег `v*`, ніхто (включно з тобою) оновлень не отримує. Оновлення в Magisk з'явиться лише після публічного релізу (§2).

---

## 2. Публічна версія — для всіх користувачів

Виконуй тільки після того, як тестова збірка стабільна.

### Кроки (приклад: з 0.0.002 на 0.0.003)

1. Переконайся, що зміни коду вже закомічені:
   ```bash
   git status
   # у списку не повинно бути незакомічених змін webroot/, service.sh тощо
   ```
2. Підніми версію:
   ```bash
   bash scripts/bump_version.sh patch
   # 0.0.002 -> 0.0.003, versionCode 2 -> 3
   ```
   Це оновить `module.prop` і `update.json`.
3. Закоміть зміни коду + версії та запуш у master:
   ```bash
   git add .
   git commit -m "chore: v0.0.003 | короткий опис змін"
   git push origin master
   ```
4. Створи і запуш тег релізу:
   ```bash
   git tag v0.0.003
   git push origin v0.0.003
   ```
   Тег запускає GitHub Actions (`release.yml`): збирає zip, оновлює `update.json` у репо, створює Release.
5. Перевір результат: GitHub → Releases → має з'явитись `v0.0.003`.
6. Зачекай 1-2 хвилини (кеш) і перевір свій Magisk: Модулі → **Оновлення** → має з'явитись 0.0.003.
   Твій телефон перевіряє `update.json` з GitHub — тож ти бачиш оновлення як звичайний користувач.

---

## 3. Якщо баг пішов у публічну версію

1. Виправ код.
2. Закоміть зміни коду.
3. Повтори §2 із кроку 2: `bash scripts/bump_version.sh patch` знову підніме версію (0.0.003 -> 0.0.004), новий тег `v0.0.004` — всі отримають фікс.

---

## 4. Часті помилки

| Ситуація | Що робити |
|---|---|
| `bash: scripts/build_test.sh: Permission denied` | `chmod +x scripts/build_test.sh`, потім знову |
| Забув закомітити зміни коду перед bump | Версія піднялась, а коду змін нема. Це не катастрофа: спочатку закоміть зміни коду, потім тег — у реліз потрапить весь коміт. Але простіше: спершу коміт коду, потім bump. |
| `git tag v0.0.003` — "tag already exists" | Тег уже створений раніше. Перевір: `git tag -l`, `git log --oneline -3`. Якщо треба реліз нової версії — роби `bump_version.sh patch` ще раз (буде 0.0.004) і тег `v0.0.004`. |
| `bump_version.sh: "Помилка: Python не знайдено"` | Потрібен Python 3. Перевір: `python --version` або `python3 --version`. |
| Zip не ставиться на телефоні | Скачай zip ще раз (можливо, обрізаний). Відкрий його архіватором і перевір наявність `module.prop`, `customize.sh`, `META-INF/`. |

## 5. Повний робочий цикл (шпаргалка)

```
Правки коду
  └─> bash scripts/build_test.sh alpha          # тестова збірка
        └─> установка на телефон → тест → баги? → правки → повтор
        └─> все ок:
              git add . && git commit -m "chore: v0.0.003 | опис"
              bash scripts/bump_version.sh patch
              git add . && git commit -m "chore: bump to v0.0.003"
              git push origin master
              git tag v0.0.003 && git push origin v0.0.003
              └─> GitHub Actions: реліз → всі (і ти) отримують оновлення
