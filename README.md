# 🏁 td2tdr

**td2tdr** — модуль для Magisk / KernelSU / KernelSU-Next, який автоматично синхронізує файл `Garage.dat` з гри **Top Drives** у папку `Download/td2tdr_sync` на вашому пристрої.

Модуль працює у фоновому режимі без необхідності втручання і надає зручний WebUI для ручної синхронізації та перегляду статистики гаража.

---

## ✨ Можливості

- 🔄 **Автосинхронізація** файлу `Garage.dat` у реальному часі
- 📂 **Копіювання** у `Download/td2tdr_sync/Garage.dat`
- 🌐 **WebUI-панель** для керування та перегляду статусу
- 📊 **Підрахунок авто** та розподіл за типами прокачки

## 📥 Встановлення

### Спосіб 1: Через менеджер модулів (рекомендовано)

1. Завантажте ZIP-файл останнього релізу зі сторінки **Releases**.
2. Відкрийте ваш менеджер модулів (Magisk / KernelSU / KernelSU-Next).
3. Оберіть **Модулі → Встановити з файлу** і вкажіть завантажений ZIP.
4. Перезавантажте пристрій.
5. Після перезавантаження модуль автоматично синхронізує `Garage.dat` у `Download/td2tdr_sync`.

### Спосіб 2: Через ADB

```bash
adb push td2tdr_v0.0.501.zip /data/local/tmp/
adb shell su -c "magisk --install-module /data/local/tmp/td2tdr_v0.0.501.zip"
adb reboot
```

## 🔄 Автооновлення

Модуль підтримує автоматичні оновлення через `update.json`, який розташований у репозиторії.

Після публікації нового релізу менеджер модулів побачить оновлення та запропонує його встановити:

- У **Magisk**: пункт "Оновлення" у картці модуля.
- У **KernelSU-Next**: так само — кнопка "Оновлення" з'явиться автоматично.

> ⚠️ **Примітка:** переконайтеся, що в `module.prop` вказано правильний `updateJson` — він уже налаштований на цей репозиторій.

## 🌐 WebUI-панель

WebUI відкривається через менеджер модулів:
- **Magisk:** Картка модуля → значок WebUI
- **KernelSU/KernelSU-Next:** Картка модуля → значок WebUI

### Основні функції панелі

| Функція | Опис |
|--------|------|
| **Синхронізувати та відкрити** | Копіює `Garage.dat` у `Download/td2tdr_sync` (у фоні) та одразу відкриває topdrivesrecords.com |
| **Миттєвий статус із кешу** | Останній стан синхронізації зберігається локально й показується одразу при відкритті панелі; повторне копіювання — тільки за кнопкою |
| **Статистика гаража** | Зайняті слоти з LED-попередженням (>95%), donut-діаграма прокачки, яскравий тег Held |
| **Аналітика** | Щоденні знімки, прогнозний слайдер 3–90 днів, середньодобовий приріст (+X / день), індикатор точності прогнозу |
| **Журнал** | Детальний лог кожного кроку синхронізації з фільтром рівнів |
| **Налаштування** | Тема (auto/light/dark), мова інтерфейсу, шляхи джерела та копії |

Кнопка **«Синхронізувати та відкрити»** має динамічну анімацію в тон статусу: спокійне зелене «дихання» коли все готове, жовте пульсування під час очікування, швидкий червоний сигнал при помилці.

## 🛠️ Для розробників

### Версіонування

```bash
./scripts/bump_version.sh patch   # 0.0.001 → 0.0.002
./scripts/bump_version.sh minor   # 0.0.002 → 0.1.000
./scripts/bump_version.sh major   # 0.1.000 → 1.0.000
./scripts/bump_version.sh 1.2.3   # конкретна версія
```

Скрипт оновлює `module.prop` та `update.json`.

> 💡 **Windows:** скрипт потребує середовище **Git Bash** (входить у Git for Windows) та **Python** у `PATH`.
> Запускайте з Git Bash, а не PowerShell: `./scripts/bump_version.sh patch`

### Створення релізу

1. Оновіть версію скриптом `bump_version.sh`.
2. Оновіть `changelog.md` — додайте запис про нову версію.
3. Закомітьте і запуште зміни:
   ```bash
   git add module.prop update.json changelog.md
   git commit -m "chore: bump to v0.0.002"
   git push origin master
   ```
4. Створіть тег:
   ```bash
   git tag v0.0.002
   git push origin v0.0.002
   ```
5. **GitHub Actions** автоматично:
   - Збере збірку в ZIP
   - Порахує `sha256`
   - Оновить `update.json`
   - Створить GitHub Release з ZIP та changelog

### Банер модуля

Банер — зображення, яке відображається у картці модуля в менеджері (Magisk / KernelSU). Посилання на нього вказується у `module.prop` полем `banner=banner.png`.

| Параметр | Значення |
|---------|----------|
| Формат | **PNG** |
| Розмір | **1024×500 px** (пропорція ~2:1, рекомендація Magisk) |
| Вага | до **100 КБ** (менше — швидший UI) |
| Фон | темний або прозорий; текст — у центрі, не в кутах |
| Шлях | корінь проєкту, поле `banner=` у `module.prop` |

**AI-промт для генерації банера** (працює у Midjourney / DALL-E / Leonardo / Bing):

## ❓ FAQ

### Як дізнатися, чи працює синхронізація?

У WebUI-панелі є індикатори статусу, а в `sync.log` (у папці модуля) ведеться повний журнал подій.

### Чи можна змінити шлях призначення?

Так — у налаштуваннях WebUI можна змінити обидва шляхи: джерело та призначення.

### Чи потрібен інтернет?

Ні. Вся робота відбувається локально на пристрої.
